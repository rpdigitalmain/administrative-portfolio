# Security policy

## Supported versions

Security fixes are applied to the latest code on the default branch. Version `1.0.0` is the initial supported release.

## Reporting a vulnerability

If private vulnerability reporting is enabled for the repository, create a private GitHub security advisory. Otherwise, contact the repository maintainers privately before sharing details publicly. Do not open a public issue for an undisclosed vulnerability.

Include as much of the following as you can:

- A concise description of the issue and its potential impact.
- The affected page, component, dependency, or configuration.
- Reproduction steps or a minimal proof of concept.
- The browser, operating system, and project version or commit, where relevant.

Avoid including credentials, private user data, or other secrets in a report. Allow maintainers time to investigate and coordinate any public disclosure.

## Scope and data handling

Reports may cover the application source, its dependencies, or its build and deployment configuration. The portfolio is a static client-side application. It does not collect or store form submissions; the WhatsApp action opens an external WhatsApp link after a phone number is configured.
